# Whatspower

**Whatspower** is a Manifest V3 Chrome extension that adds privacy and convenience tools to WhatsApp Web. It is written in TypeScript and ships only locally bundled JavaScript, HTML, and CSS.

> **Compatibility warning:** WhatsApp Web is a frequently changing, closed-source web application. It does not provide a supported extension API for read receipts, typing indicators, deleted-message recovery, or status extraction. Whatspower therefore distinguishes DOM features that can be implemented locally from protocol hooks that are best-effort. Do not treat Ghost Read or Activity Mask as a guarantee that a receipt or presence signal was not sent.

## Features

| Feature | What this build does | Practical limitation |
|---|---|---|
| Ghost Read | Installs a narrow MAIN-world hook for explicitly named `sendSeen` entry points and recognizable JSON/text read-receipt commands. | Most WhatsApp traffic uses opaque binary protocol frames and private internal modules. Those frames are deliberately left untouched. This cannot guarantee read receipts are blocked. Prefer WhatsApp's own privacy controls for dependable behavior. |
| Activity Mask | Applies the same conservative filtering to recognizable JSON/text `composing`, `typing`, and `recording` commands. | It cannot reliably identify commands inside an opaque binary frame or an internal method that WhatsApp does not expose. |
| Quick Chat | Opens `https://web.whatsapp.com/send?phone=...` from the popup, with a country calling-code selector. | The number must be valid and registered on WhatsApp. The extension does not bypass WhatsApp account, availability, or blocking restrictions. |
| Status Downloader | Adds a download control to a detected status viewer. It downloads DOM-accessible image/video media or saves visible text as `.txt`, using the requested contact/date/time filename pattern. | WhatsApp may use expiring, protected, or inaccessible media URLs. Contact name/number extraction is heuristic. Blob transfers are capped at 30 MB. |
| Message Recovery | Caches text from message containers that are rendered in the open chat. It can also cache already-loaded `blob:`/`data:` media attachments up to 8 MB each. If a matching message container later shows a deleted-message placeholder, the cached copy is displayed inline. | It cannot recover messages that were never rendered and cached, messages deleted before the extension observed them, or media that was not already accessible in the DOM. This is not a decryption tool. Data is stored in the browser's IndexedDB and is not uploaded. The cache prunes oldest records when it exceeds approximately 1,200 messages or 100 MB. |
| Privacy Mode | Blurs contact names/photos, message content, selected chat titles, selected chats, and messages matching a user keyword list. Hover or keyboard focus reveals blurred content. | Selectors depend on WhatsApp's current DOM and may need maintenance after redesigns. |
| Speed Voice | Adds a playback-rate selector (1× through 3×) to native `<audio>` elements found on the page. | Some WhatsApp voice-note players may not expose an HTML audio element. Those custom players cannot be controlled by this DOM-only implementation. |

## Installation (unpacked)

1. Install Node.js 20 or newer.
2. In this project directory, run:

   ```bash
   npm install
   npm run typecheck
   npm run build
   ```

3. Open `chrome://extensions/` in Chrome.
4. Turn on **Developer mode**.
5. Select **Load unpacked** and choose the `whatspower-extension` project folder (the folder containing `manifest.json`, not `src/` or `dist/`).
6. Open or refresh `https://web.whatsapp.com/`. Pin Whatspower if you want quick access to the popup.

After changing source files, run `npm run build`, then click **Reload** on the extension card and refresh WhatsApp Web.

## Architecture

- **Manifest V3:** registers two content scripts at different execution worlds. `main-world.js` runs at `document_start`; `isolated-world.js` runs at `document_idle`.
- **MAIN world:** contains no Chrome API calls. It receives narrowly scoped settings through a `window.postMessage` bridge, patches only explicitly named functions that happen to be exposed, and inspects only small JSON/text WebSocket frames. It does not decode or modify opaque WhatsApp protobuf traffic.
- **ISOLATED world:** owns DOM selectors, MutationObserver scanning, UI injection, privacy blur, IndexedDB recovery cache, audio controls, and the status download request.
- **Background service worker:** is intentionally stateless. It handles download requests and initializes storage defaults. Settings are read from `chrome.storage.local`; no active configuration is kept in service-worker globals.
- **Popup:** provides Quick Chat, feature toggles, keyword management, selected-chat management, and a recovery-cache clearing action.
- **Storage:** settings are stored in `chrome.storage.local`. Recovered message text and eligible visible attachment blobs are stored in IndexedDB (`whatspower-recovery`) for the current browser profile.

## Privacy and data handling

- The extension does not send chat content to a Whatspower server; there is no Whatspower server component.
- Message Recovery stores content locally in the browser profile. Anyone with access to that Chrome profile may be able to inspect its local browser data. Turn the feature off and use **Clear cache** from the popup while WhatsApp Web is open to remove the extension's recovery records.
- Downloaded statuses are saved through Chrome's Downloads API.
- The MAIN-world bridge is visible to the page. It carries only two boolean settings. It is not a security boundary against the page itself.
- Use the extension only with content you are authorized to view and retain, and respect other people's privacy and applicable law.

## Development notes

- `npm run typecheck` runs strict TypeScript checking.
- `npm run build` bundles each TypeScript entry point with esbuild and copies popup assets into `dist/`.
- All runtime code is local. There are no remote scripts, `eval`, dynamic imports, or remote-code execution paths.
- The content script uses attribute-oriented selectors such as `data-testid`, `aria-label`, and semantic roles rather than generated CSS-module class names.
- One debounced `MutationObserver` handles SPA changes. Element-specific controls are tracked with `WeakMap`s, and the observer is disconnected on `pagehide`.
- Cross-context messaging is guarded so extension reloads do not leave unhandled context-invalidated errors in the page.

## Troubleshooting

- **Popup says the active tab cannot be reached:** make sure WhatsApp Web is open and reload the page after reloading the extension.
- **A feature disappears after a WhatsApp update:** inspect the current DOM in DevTools and update the corresponding semantic/data-testid selector. WhatsApp can rename or remove its attributes without notice.
- **Ghost Read / Activity Mask does not work:** this is expected when WhatsApp uses binary protocol messages or private methods that are not exposed on `window`. The extension intentionally does not guess at binary payloads because dropping an unknown frame can break WhatsApp messaging.
- **Status download fails:** the selected status may not expose a readable media URL, may require an unavailable page credential, or may exceed the in-page transfer cap.
- **Deleted message is not recovered:** recovery is prospective. The extension must have seen and cached that message before WhatsApp replaced it with a deletion placeholder.
- **Voice speed control is missing:** the current WhatsApp voice-note player may not contain a native `<audio>` element.
